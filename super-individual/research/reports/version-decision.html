记录日期：2026-08-17
当前状态：AI 初判，待产品确认范围后执行
需求类型：不改后端和数据结构的前端信息架构验证 Demo
预计周期：7 个工作日，2026-08-17 至 2026-08-25
对应 Q3 主线：Flow A 为主，Flow B 与 Flow C 做必要衔接

一、为什么做

当前首页不是功能缺失，而是高价值功能的优先级、入口层级和资源组织方式不够清楚：

  1. 高频功能与重要支持入口并列或隐藏，用户需要自行判断下一步。
  2. 资源以话题、活动和内容栏目分散出现，用户难以理解不同内容、工具和服务的归属及使用方式。
  3. 内容卡片主要展示标题、类型和时长，没有充分对应学生当下的情绪或使用场景。
  4. 首页首屏同时承载打卡、AI 伙伴、解忧信箱、话题入口、活动 Banner 和底部导航，信息丰富但行动主次不够明确。

二、证据来源

2.1 产品需求反馈

  • 产品要求：不动后端和数据结构；业务模块可以进行合并或重组。
  • 产品优先级：优先解决高频或高优先级模块位置较深、资源零散且没有模块化的问题。

2.2 市场反馈

  • 市场反馈图：AI 心理伙伴系统，包含校园信箱、学生资源、首页布局和对话首屏建议。
  • 关键启发：高价值模块应在首页获得更清晰的权重；资源应按学生可理解的方式组织；对话首屏需要更强的陪伴感和开始引导。
  • 市场反馈属于外部启发，不直接等同于本产品需求；本轮只吸收与当前 Demo 范围一致的布局和资源组织方向。

三、核心决策

3.1 Demo 定位

本轮不是完整新版本，也不是新功能开发，而是：

在不改后端和数据结构的前提下，验证首页信息架构、业务模块重组和资源入口前置，能否降低用户找到下一步的判断成本。

3.2 Demo 只验证三条主线

主线 目标 交付深度
Flow A：首页启动中枢 用户打开首页后能快速理解并开始一个行动 高保真、可点击、做主流程闭环
内容 / 工具 / 服务分层 用户能区分心理剧场、知心姐姐、情绪工具箱和解忧信箱，并找到合适入口 首页按产品属性拆分表达，不把四者强行合并为同一种资源卡
Flow B/C 衔接 从首页进入 AI 或完成一次轻行动后能回到首页 只做必要的衔接节点，不扩展完整能力

四、具体做什么

4.1 首页重组

建议结构：

  1. 顶部状态与支持入口：保留用户信息；将解忧信箱从孤立按钮升级为清晰的安全支持入口。
  2. 主行动区：保留心情打卡，但从“必须完成的任务”改为“今天从这里开始”的状态入口。
  3. AI 伙伴区：保留现有 AI 能力，优化首屏角色表达、开场话题和继续对话入口；“现在需要什么帮助”直接进入 AI 对话，不新增中间分流页。
  4. 快捷行动区：合并心理剧场、轻训练、学生资源、自我测评等入口，控制为 3–4 个明确动作。
  5. 今日推荐区：根据现有可用内容做静态或前端映射推荐，展示 1 个主推荐和 1–2 个次级入口。
  6. 底部导航：本轮不改后端功能和导航能力，只重新确认首页与探索页职责，避免底部六项继续承担所有分流。

4.2 内容资源与工具分流

利用现有内容做前端重组，不新增内容管理系统。心理剧场、知心姐姐属于内容资源；情绪工具箱属于功能集合；解忧信箱属于通信服务，不强制合并为一个“学生资源中心”。内容资源可以补充学生场景标签：

  • 我有点烦 / 压力大
  • 睡不着 / 想放松
  • 学业与考试
  • 朋友与同学
  • 家庭与沟通
  • 想了解自己
  • 求助与安全

图文 / 视频课件卡片可统一展示内容类型、使用时长、适用场景和明确动作；心理剧场仍保留月刊 Banner 和当期舞台结构，不降级为普通资源卡。情绪工具箱用工具入口表达，解忧信箱用通信状态表达。

4.3 AI 对话首屏

  • 保留现有对话能力和角色关系。
  • 增加 3–4 个低压力开场话题。
  • 文本对话作为现有基础能力；不在本轮承诺实时语音能力。
  • 明确安全与保密说明的可达入口，避免市场反馈中的“陪伴感”演变成不受控的成人化关系表达。

4.4 轻完成反馈

选一个现有轻行动作为验证样本，例如 2 分钟呼吸或短练习：

首页状态入口 → 选择状态 → AI 接住 → 今日推荐 → 完成反馈 → 首页回流。

不做完整地图、商店、积分体系或新的成长数据结构。

五、明确不做什么

  • 不改后端接口、数据库和数据结构。
  • 不新建完整资源管理、推荐或测评结果系统。
  • 不新增 AI 能力，不实现真实实时语音对话。
  • 不重做所有业务页面和所有历史内容。
  • 不把所有模块都做成同等大小的首页卡片。
  • 不恢复“功能越多越丰富”的首页陈列逻辑。
  • 不把市场反馈中的校园信箱、MBTI、积极心理等内容直接当作本轮新增需求。

七、验收指标

本轮 Demo 不以“页面做完”为完成标准，而以以下指标判断是否值得进入下一阶段：

  1. 路径可发现性：5 名内部体验者中，至少 4 人能在 10 秒内指出“我现在想放松 / 想聊天 / 找资源”分别从哪里开始。
  2. 模块理解度：5 名体验者中，至少 4 人能说出首页主行动和资源中心的区别。
  3. 资源可找性：5 名体验者中，至少 4 人能在 20 秒内找到一个与“考试压力”或“睡不着”相关的资源。
  4. 流程完整性：Flow A 至少跑通 1 条完整闭环；Flow B 和 Flow C 至少各有 1 个可回流节点。
  5. 技术边界：Demo 中 100% 的新增展示和重组内容都能标注为现有功能、现有内容映射或静态模拟，不引入未确认的后端依赖。

八、需要产品拍板的事项

  1. 已确认：“现在需要什么帮助”直接进入 AI 对话，不新增独立帮助分流页；首页仍保留情绪打卡作为状态记录入口。
  2. 已修正：不再强制用“学生资源中心”统一承载心理剧场、知心姐姐、解忧信箱和情绪工具箱；四者按月刊内容、联名资源、通信服务和工具集合分别表达。
  3. 本轮资源中心是否纳入自我测评入口；如果纳入，先做入口验证，不做完整测评结果体系。
  4. 解忧信箱是否属于首页固定一级入口，还是作为“求助与安全”统一入口的一部分。

九、状态与后续

  • 已拍板：不改后端和数据结构；Demo 重点解决入口深、资源散和模块优先级不清；“现在需要什么帮助”直接进入 AI 对话。
  • AI 初判：首页、资源中心、AI 首屏和轻行动反馈组成最小有效 Demo。
  • 待验证：用户是否更快找到下一步；学生是否理解资源中心；用户是否愿意从“现在需要什么帮助”直接开始 AI 对话。

10.2 可以做静态演示，但不能承诺真实上线

以下内容可以作为 Demo 的状态模拟或视觉验证，但本轮不接真实累计逻辑：

  • IP 记得上次情绪、用户间隔几天后回来的示例文案。
  • 个人空间随着来访次数变丰富的概念画面。
  • IP 换装里程碑和情绪纪念物的局部浮层。
  • “小回顾”叙事卡片。

这些内容可以帮助产品判断方向，但必须标注为静态模拟 / 待数据能力确认，不能在 Demo 中表现成已有真实能力。

10.3 本轮暂缓

以下内容依赖后端、数据结构或新的成长系统，本轮不进入 Demo 主线：

  • 真正将连续 5 天改成累计 10/30/60 次的生产机制。
  • 三套独立货币：星星碎片、情绪互动次数、来访次数。
  • 基于历史数据自动触发邻居推荐和个性化推荐。
  • 完整空间建造、解锁、持久化和长期成长系统。
  • 完整 IP 换装资产、里程碑奖励和兑换逻辑。
  • 社交拉新、邀请礼物或同学动态机制。
  • 旅行地图、完整叙事探索和新地图数据。

10.4 本轮的正确使用方式

Finch 文档里最有价值的不是“做空间、做货币、做连续奖励”，而是这条底层原则：

从“督促用户持续使用”转向“用户什么时候回来都能被接住”。

本轮先把这条原则落实到首页入口、情绪打卡、AI 对话、资源推荐和轻完成反馈；复杂的累计成长机制保留为后续产品结构评估，不因 Demo 直接承诺。

11.4 后续视觉与体验优化

  1. 整体像通用桌面 SaaS 工作台：白色卡片、顶部搜索、左右数据栏弱化了儿童心理陪伴产品的温度，与现有 IP 和场景资产割裂。
  2. 中央 AI 区面积过大但信息不足：大面积留白只有 Emoji、问候和输入框，缺少真实 IP 形象、开场话题和安全说明入口。
  3. 首页仍然信息平权：左侧 5 个入口、中央 4 个推荐、右侧 3 个模块同时出现，用户仍需判断很多内容，只是从横向平权变成三栏平权。
  4. 解忧信箱定位偏弱：目前是普通推荐卡，未体现其“有人回应 / 求助与安全支持”的特殊价值。
  5. 资源推荐缺少行动信息：未统一展示资源类型、使用时长、适用场景和明确动作。
  6. 完成反馈和首页回流尚未展示：本轮陈列 Demo 可不做；进入交互 Demo 后再补 Flow C。
  7. IP 切换悬浮按钮缺少说明：只有 Emoji，没有角色名称和选择反馈；真实形象缺失会降低 Demo 说服力。
  8. 指标没有证据：页面中的“聚焦度 +60%、可达性 +80%、路径 -50%”没有测试来源，应删除或改成待验证指标。
  9. 开发周期口径不一致：页面写 1–2 周，当前正式方案为 7 个工作日；对外只保留一个周期口径。

11.5 推荐的页面结构修正版

  1. 顶部：保留现有搜索、用户信息，并让 Logo 明确承担返回首页的作用；解忧/求助入口需保持可发现。
  2. 左侧状态区：情绪打卡主卡，保留 6 个状态词和明确 CTA；选择后进入 Flow A。
  3. 中央 AI 区：真实 IP 形象 + “现在需要什么帮助” + 3–4 个开场话题 + 直接输入。
  4. 资源区：当前业务模块卡片可以保留；建议补充场景标签，或制作“业务模块版 / 学生场景版”两种方案进行对照。
  5. 支持区：解忧信箱和安全支持保持显眼，但不和普通热门内容混排。
  6. 导航：本轮可以不保留底部导航，但需在后续二级页验证“返回首页”和跨模块路径；是否恢复精简导航由验证结果决定。
  7. 回流状态：完成打卡或轻行动后，首页展示“今天已记录 / 已完成一小步”的轻反馈。

十五、默认版心情打卡二级页面方案（2026-08-18）

15.1 目标与边界

本轮目标不是重做心情打卡功能，而是在原有“选心情 → 选原因 / 自己填写 → 心情日历”基础上，优化信息层级、表达方式和情绪反馈。

明确不做：后端 API 改造、数据结构重构、多选原因、连续打卡奖励、空间成长、真实邻居智能推荐、跨天记忆字段和新的业务模块。

15.2 六类心情的设计判断

原版五级刻度主要表达“开心程度”，适合记录强弱，但难以区分焦虑、疲惫、生气等对后续陪伴方式不同的状态。

本轮 Demo 采用六种常见状态：

状态 设计价值
开心 记录积极体验和值得高兴的事
还好 承接平常状态，不要求用户必须“很好”
难过 为倾听、倾诉和情绪支持留下语义入口
生气 识别在意、冲突和边界感受
焦虑 未来可关联呼吸、放松和考前支持
疲惫 未来可关联休息、睡眠和低负担练习

同时保留“说不清，也可以先记下来”作为低压力兜底入口。它不是第七种情绪分类，而是允许用户在无法命名感受时继续完成记录。

该口径对下一次功能大改版更有利，但本轮仅作为前端 Demo 展示口径；正式开发前需确认后端枚举是否兼容。

15.4 主 IP 与邻居的关系设计

  • 主 IP 是全局陪伴者，负责持续关系、倾听和回应。
  • 邻居是情境化共鸣者，只在完成态出现一位，根据心情或原因提供一句短反馈。
  • Demo 采用“1 位当前主 IP + 1 位邻居”的层级，不让多个角色平级发言。
  • 邻居反馈先以静态映射表达角色家族和归属感，正式产品再决定是否接入真实匹配逻辑或工具跳转。

15.5 视觉表达决策

  • 选择阶段保留图标：图标帮助学生快速扫读和建立亲和感，但缩小为辅助线索。
  • 文字是主要信息：选项名称清晰可读，选中状态通过边框、底色和勾选表达。
  • 输出阶段只显示文字：不把图标塞入“今天我觉得……因为……”句子，避免破坏语言连续性。
  • 原因内容全部保留，按“学校里的事 / 家里的人 / 身体和生活”在同一屏分组，不新增分类跳转。

15.9 首页状态继承与融合版 v2（2026-08-18）

必须修正的交互问题

首页已经完成“今日状态”选择后，心情打卡二级页不应再次询问相同问题。重复选择会造成两个负面感受：一是用户怀疑刚才的操作没有生效；二是流程产生无意义回退。因此两版统一采用：

首页选择状态 → 直接选择原因 / 自己写 → 完成反馈
